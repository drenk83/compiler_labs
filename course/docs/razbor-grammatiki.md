# Разбор грамматики

Распознаватель решает только одно: принадлежит ли текст учебному подмножеству. Сценарий не исполняется, подстановки не раскрываются. Верный текст принимается молча, код 0. При первой ошибке печатается одна строка и код 1.

Пояснение есть не у каждой ошибки. Где оно есть, ниже написан текст сообщения. Где его нет, в stderr только `Error: line N`.

Номер строки считается с 1. Перевод строки flex учитывает в момент чтения символа, поэтому ошибка на этом токене часто относится к следующей строке. У `local` без аргументов сообщение приходит не на строку слова `local`, а на следующую.

Во всех примерах ниже, кроме раздела про шебанг, первая строка файла — `#!/bin/bash`.

## Шебанг

Правило `program`: файл начинается с шебанга, дальше список команд. Список может быть пустым.

Верно. Файл из одного шебанга:

```bash
#!/bin/bash
```

Верно. После шебанга команды и комментарий:

```bash
#!/bin/bash
# комментарий
echo x
```

Неверно. Пустой файл, текст без шебанга, комментарий до шебанга, шебанг через env:

```bash
echo hi
```

```bash
#!/usr/bin/env bash
echo hi
```

Сообщение: `Error: line 1: missing shebang`.

Неверно. После пути есть лишний текст, или строка шебанга кончается на `\r` (файл с CRLF):

```bash
#!/bin/bash -e
echo hi
```

Сообщение: `Error: line 1: extra text in shebang`. После `#!/bin/bash` можно оставить только пробелы и табы.

## Список команд и разделители

`list` — тело файла, ветка `then` / `else` и тело между `do` и `done`. Он может быть пустым. `stmt_seq` — команды подряд. Между ними `separator`: `;`, `&` или перевод строки. `nl_opt` забирает лишние переводы строки, чтобы пустая строка не стала пустой командой.

Верно. Пустые строки, хвостовая точка с запятой и фон:

```bash
#!/bin/bash

echo x;

echo y &
```

Неверно. Пустая команда из двух точек с запятой, и `;;` вместо `;`. Две точки с запятой — один токен `;;`, он закрывает ветку `case`, а не две команды:

```bash
#!/bin/bash
echo x;;
```

Пояснения нет, только номер строки.

Неверно. `&` нельзя поставить там, где нужен разделитель `sep` (перед `then` и `do`). `&` заканчивает команду, но в `sep` его нет:

```bash
#!/bin/bash
if true & then echo x; fi
```

## Цепочки &&, || и конвейер

`and_or` — конвейеры через `&&` и `||`. `pipeline` — команды через `|`. Конвейер стоит ниже, поэтому в `a && b | c` сначала связывается `b | c`, и только потом результат с `a`. После `&&`, `||` и `|` может быть пустая строка.

Верно:

```bash
#!/bin/bash
true &&
false || true
echo a | wc -l
a && b | c
```

Это же правило `and_or` является условием `if`, `elif`, `while` и `until`. Одна команда — частный случай такой цепочки.

## Простая команда и присваивание

`simple_command` — имя, аргументы и перенаправления в конце. Имя (`cmd_name`) — то же слово, что аргумент: имя, обычное слово, строка или подстановка. Присваивание среди аргументов остаётся аргументом.

`assignment` — целая команда: токен `NAME=` или `NAME=` и следующее слово. Пробела вокруг `=` в самом токене нет. `FOO=1` сканер отдаёт одним токеном. `FOO=` и следующее слово `bar` — присваивание из двух частей.

Верно:

```bash
#!/bin/bash
echo x
"echo" x
$cmd x
$(echo echo) x
echo FOO=1
FOO=1
FOO=
name="World"
FOO= bar
```

Неверно. Префикс присваивания перед другой командой. Грамматика видит присваивание `FOO=1`, а следом ещё одну команду `echo`, и не знает, куда её деть:

```bash
#!/bin/bash
FOO=1 echo x
```

Пояснения нет.

Неверно. Имя цикла `for` и `select` — только `ID`, не слово с дефисом:

```bash
#!/bin/bash
for a-b in x; do echo x; done
```

## Слово, кавычки и ключевые слова

`word` — имя, обычное слово, строка или подстановка. В кавычках `$` не разбирается: `"Hello, $name!"` — одна строка. Пустые `''` и `""` можно. Незакрытая кавычка и перевод строки внутри кавычки — ошибка, пояснения нет.

Ключевые слова `done`, `in`, `select` и остальные из списка ключевые в любой позиции, не только в начале команды. Поэтому `echo done` и `echo in` не принимаются. Пояснения нет.

Вне кавычек `\` не входит в слово. Скобки `[ ] { }` в слово не входят, поэтому `ls [abc]*` и `echo {a,b}` отвергаются.

Одиночный `!` — обычное слово, не отрицание. Запись `if ! [ a ]` не является отрицанием проверки: `!` читается как команда.

```bash
#!/bin/bash
if ! [ a ]; then echo x; fi
```

## Проверка в квадратных скобках

`test_command`: слова между `[` и `]`. Слов может не быть. Знаки `-f`, `=` и `-lt` остаются словами. После `]` может быть перенаправление.

Верно:

```bash
#!/bin/bash
[ ]
[ -f "$1" ]
[ -f "$1" ] > /tmp/f
if [ -f "$1" ] 2> /tmp/err; then echo ok; fi
```

Неверно. Две открывающие скобки. Пробел между ними сканер выбрасывает, поэтому `[ [` — тот же отказ:

```bash
#!/bin/bash
[[ -f x ]]
```

Сообщение: `Error: line N: [[ is not supported`.

## Перенаправления

`redir_list` — ноль или больше перенаправлений в конце команды. Можно `>`, `>>`, `<`, `2>` и `2>&1`. У `2>&1` цели нет. Цель остальных — слово, не присваивание и не ключевое слово. Имя файла `in` не годится: `in` везде ключевое. Несколько перенаправлений можно писать подряд.

Они стоят в конце простой команды, проверки `[ ... ]`, составной команды и функции. После присваивания и после `local` их нет.

Верно:

```bash
#!/bin/bash
echo x > /tmp/out >> /tmp/log < /tmp/in 2> /tmp/e 2>&1
echo x > "$file"
if true; then echo x; fi > /tmp/out
( echo y ) | cat
```

Неверно. Два знака `<` подряд — here-документ. Отдельного токена `2>>` нет: такая запись не собирается в одно перенаправление.

```bash
#!/bin/bash
cat <<EOF
hi
EOF
```

Сообщение: `Error: line N: here-document is not supported`.

## Подстановки

Вне кавычек: `$имя`, `$1`, `$#`, `$@`, `$*`, `$$`, `$?`, `${имя}` и `$(...)`. Внутри `$(...)` тот же список команд, без шебанга. Перевод строки внутри подстановки можно.

Верно:

```bash
#!/bin/bash
echo $a $1 $# $@ $* $$ $? ${name}
echo $(echo hi)
echo $(
  echo hi
)
echo "Hello, $name!"
$((count + 1))
```

Последняя строка для распознавателя — команда, имя которой подстановка. Арифметика не считается. `echo $((count + 1))` читается как подстановка команды, внутри которой ещё один подшелл.

Неверно. В `${...}` только голое имя. Значение по умолчанию, замена и массивы не входят:

```bash
#!/bin/bash
echo ${var:-default}
```

Неверно. Подстановка процесса и обратные кавычки. Пояснения нет:

```bash
#!/bin/bash
cat <(echo x)
```

```bash
#!/bin/bash
echo `echo x`
```

## if и elif

`if_clause`: условие — один `and_or`, затем `sep`, затем `then`, список команд и `fi`. Веток `elif` может быть несколько. `else` необязателен. Тело после `then` может быть пустым.

`sep` — точка с запятой или перевод строки, и после них ещё пустые строки. Знак `&` в `sep` не входит.

Верно:

```bash
#!/bin/bash
if true; then echo x; fi
if true
then
  echo x
fi
if true; then fi
if true && false; then echo ok; fi
if echo a | grep a; then echo ok; fi
if true; then echo a; elif false; then echo b; else echo c; fi
```

Неверно. Нет разделителя перед `then`. То же для `elif`:

```bash
#!/bin/bash
if true then
  echo x
fi
```

Сообщение: `Error: line N: missing ';' or newline before then`.

Неверно. Две команды через `;` не являются одним условием. Первая точка с запятой уже закрывает условие, и `false` оказывается на месте `then`:

```bash
#!/bin/bash
if true; false; then echo x; fi
```

Пояснения нет.

Неверно. Ветку `if` нельзя закрыть словом `done`:

```bash
#!/bin/bash
if true; then
  echo x
done
```

Пояснения нет. В тесте на эту запись сообщение `Error: line 4`.

## while и until

Та же схема, что у `if`: условие — один `and_or`, перед `do` нужен `sep`, тело между `do` и `done`. Тело может быть пустым. `until` устроен так же, как `while`. Распознаватель не смотрит, истинно условие или нет.

Верно:

```bash
#!/bin/bash
while true; do echo x; done
while true; do
done
until false; do echo x; done
```

Неверно. Нет разделителя перед `do`:

```bash
#!/bin/bash
while true do
  echo x
done
```

Сообщение: `Error: line N: missing ';' or newline before do`.

## for и select

Две формы. Со списком: `for имя in слова`. Без списка: `for имя`. Перед `do` снова `sep`. Имя — только `ID`. Список после `in` может быть пустым. По словам списка распознаватель не проходит: он проверяет запись, а не выполняет цикл.

`select` имеет те же две формы. Меню и переменная `REPLY` — поведение оболочки, грамматика их не описывает.

Верно:

```bash
#!/bin/bash
for name in a b; do echo "$name"; done
for name; do echo x; done
for name in; do echo x; done
select name in a b; do echo x; done
select name; do echo x; done
```

Неверно. Нет разделителя перед `do`, и со списком, и без него:

```bash
#!/bin/bash
for name in a b do echo x; done
```

Сообщение: `Error: line N: missing ';' or newline before do`. У `select` то же пояснение.

## case

`case слово in`, затем ноль или больше веток, затем `esac`. Слово `in` обязано стоять сразу после разбираемого слова. Точка с запятой или перевод строки на его месте не заменяют `in`: для них отдельные отказы. После `in` пустые строки можно.

Образец — имя, слово или строка. Несколько образцов в одной ветке пишутся через `|`. После образцов `)`, тело и обязательные `;;`.

Верно:

```bash
#!/bin/bash
case $x in
a|b) echo ok ;;
*) echo other ;;
esac
```

```bash
#!/bin/bash
case x in esac
```

```bash
#!/bin/bash
case x in
"a b") echo ok ;;
esac
```

Неверно. Нет `in`. Три записи дают одно и то же пояснение: `case x esac`, `case x;` и перевод строки вместо `in`:

```bash
#!/bin/bash
case x esac
```

```bash
#!/bin/bash
case x
in
a) echo ok ;;
esac
```

Сообщение: `Error: line N: case requires in`. Во втором фрагменте `in` на следующей строке уже не спасает: перевод строки распознан как отказ раньше.

Неверно. Ветка дошла до `esac` без `;;`:

```bash
#!/bin/bash
case x in
a) echo ok
esac
```

Сообщение: `Error: line N: case item must end with ;;`.

## Функция, группа и подшелл

Три формы функции. Тело — группа в фигурных скобках. Перед телом можно оставить пустые строки.

```bash
#!/bin/bash
name() { echo x; }
function name { echo x; }
function name() { echo x; }
name() { }
```

После объявления может стоять перенаправление. Хвост может быть пустым:

```bash
#!/bin/bash
name() { echo x; } > out
```

Группа `{ ... }` — та же конструкция, что тело функции. Она может быть отдельной командой. Пустые `{ }` и `( )` принимаются. В непустой группе перед `}` нужны `;` или перевод строки.

Верно:

```bash
#!/bin/bash
{ echo x; }
{ }
( echo y )
( )
((echo z))
```

`((echo z))` — два подшелла, не арифметика. Пробел между скобками сканер выбрасывает.

Неверно. Внутри группы есть команда, а перед `}` нет разделителя. У функции то же сообщение, потому что тело — та же группа:

```bash
#!/bin/bash
{ echo x }
```

```bash
#!/bin/bash
name() { echo x }
```

Сообщение: `Error: line N: missing ';' or newline before '}'`.

У составной команды перенаправление стоит после неё целиком: `if ... fi > out`, `{ echo x; } > out`, `( echo y ) | cat`.

## local

`local` требует хотя бы один аргумент. Аргумент — имя, `NAME=` или `NAME=` и слово. Несколько аргументов пишутся подряд. Стоит ли объявление внутри функции, грамматика не проверяет: `local` на верхнем уровне текста тоже принимается.

Верно:

```bash
#!/bin/bash
f() { local a b=1; }
local a=1
f() { local a= b; }
```

Последняя запись — спорная для грамматики, но она принимается. Сканер выбрасывает пробел и отдаёт `a=` и следом имя `b`. Это имя можно прочитать как значение присваивания (один аргумент) или как следующий аргумент (два аргумента). Оба разбора текст принимают. Bison выбирает сдвиг, то есть один аргумент `a=` со значением `b`. На ответ программы спор не влияет.

Неверно. Нет ни одного аргумента:

```bash
#!/bin/bash
local
```

Пояснения нет. Из-за перевода строки номер в сообщении — следующая строка, не строка слова `local`.

Перенаправление после `local` не предусмотрено.

## then и do не на своём месте

Если `then` или `do` стоят там, где должна быть команда, срабатывает `stray_keyword`.

```bash
#!/bin/bash
then
```

Сообщение: `Error: line N: unexpected then`. Для `do` — `unexpected do`.

`fi`, `done`, `else`, `elif` и `esac` так не помечены. Они закрывают тело, а тело может быть пустым. Автомат не отличает пустой список от команды из одного такого слова. Одиночное `fi` отвергается, но без этого пояснения: в сообщении только номер строки.

## Что отвергается ещё до грамматики

Эти записи не доходят до правил выше. Их режет сканер.

| Запись | Что происходит |
|---|---|
| пустой файл, нет шебанга, `#!/usr/bin/env bash`, комментарий до шебанга | `missing shebang` |
| `#!/bin/bash -e`, шебанг с `\r` | `extra text in shebang` |
| `echo done`, `echo in`, `echo select` | ключевое слово не на своём месте, пояснения нет |
| `echo a\b`, `ls [abc]*`, `echo {a,b}` | символ не входит в слово |
| незакрытая кавычка, перевод строки внутри кавычки | пояснения нет |
| байт не из ASCII | пояснения нет |

Арифметический `for (( ... ))`, массивы `a=(1 2)`, `source` и `coproc` отдельными конструкциями не описаны. Скобки в них читаются как функция, группа, подшелл или подстановка, и запись либо принимается в этом другом смысле, либо отвергается как обычная синтаксическая ошибка.
