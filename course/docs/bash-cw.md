# bash-cw

Входной язык распознавателя. Это учебное подмножество синтаксиса bash, не шелл и не «весь bash». Принадлежность текста языку определяет грамматика ниже, а не поведение GNU bash.

## Контракт распознавателя

Вход: путь к файлу `.sh` (или stdin, если путь не дан).

| Исход | stdout | stderr | код |
|---|---|---|---|
| текст ∈ bash-cw | пусто | пусто | 0 |
| иначе | пусто | `Error: line N` или `Error: line N: text` | 1 |

`N` — номер строки (с 1), на которой обнаружена ошибка. Дальше разбор не идёт. Для токена перевода строки flex увеличивает счётчик при чтении этого символа, поэтому ошибка на таком токене относится к следующей строке. Пояснение `text` есть у трёх отказов: `missing shebang`, `extra text in shebang`, `here-document is not supported`.

Строка шебанга — строка 1. Пустой файл — `Error: line 1: missing shebang`.

## Программа

Файл начинается с шебанга. Комментарии и команды — только после него.

```
program     ::= shebang [ NL body ]
shebang     ::= '#!/bin/bash' [ spaces ]
body        ::= { NL | comment NL | complete_command }
```

- Шебанг — ровно `#!/bin/bash`, затем только пробелы/табы до конца строки. Не `#!/usr/bin/env bash`, не аргументы после пути.
- Файл из одного шебанга (с NL или без) принадлежит языку.
- Пустой файл не принадлежит.
- Текст — ASCII. Байт вне ASCII — ошибка на этой строке.
- Конец строки — `\n`.

Комментарий: `#` до конца строки, если `#` стоит на границе токена (после пробела, `;`, NL, в начале строки тела). `#` внутри слова не начинает комментарий (`$#` — подстановка, `foo#bar` — одно слово). Внутри `'...'` / `"..."` комментариев нет.

## Токены

Пробел и таб разделяют токены и иначе незначимы.

**Ключевые слова** (только целиком, не часть слова):  
`if` `then` `elif` `else` `fi` `while` `until` `do` `done` `for` `select` `in` `case` `esac` `function` `local`

**Операторы:**  
`|` `||` `&` `&&` `;` `<` `>` `>>` `2>` `2>&1` `(` `)` `{` `}` `[` `]`

**Имя (`ID`):** `[A-Za-z_][A-Za-z0-9_]*`

**Присваивание (`ASSIGN`):** `ID=` или `ID=` сразу за ним значение без пробела: WORD, STRING или подстановка (`count=0`, `name=`, `path=/tmp/a`, `name="World"`, `name=$1`). Пробел вокруг `=` запрещён для этой конструкции: `name = 1` — это три отдельных слова, не присваивание.

**Слово (`WORD`):** непробельная последовательность ASCII без операторов, кавычек и `#` на границе. В том числе `echo`, `apt-get`, `foo/bar`, `-lt`, `--help`, `+x`, `2`, `*.txt`.

**Строка:** `'...'` или `"..."`. Это один токен.

- Внутри кавычек подстановки **не** разбираются: `"Hello, $name!"` — строка, не `$name`.
- В одинарных кавычках `'` внутри быть не может.
- В двойных `\"` и `\\` не закрывают строку; прочие байты непрозрачны.
- Неэкранированный NL внутри строки — ошибка на этой строке.
- Пустые `''` и `""` допустимы.

**Подстановка** (только вне кавычек):

- `$ID` `$`+цифры `$#` `$@` `$*` `$$` `$?`
- `${ID}` — только простое имя, без `:-`, `/` и прочего
- `$( list )` — внутри тот же список команд, что в теле программы, без шебанга; вложенность можно

## Команды

```
complete_command ::= and_or [ ';' | '&' ] [ NL ]
                   | and_or NL

and_or           ::= pipeline
                   | pipeline '&&' [ NL ] and_or
                   | pipeline '||' [ NL ] and_or

pipeline         ::= command
                   | command '|' [ NL ] pipeline

command          ::= simple_command
                   | assignment
                   | test_command
                   | compound_command { redir }
                   | function_def
                   | local_stmt

compound_command ::= if_clause | while_clause | until_clause
                   | for_clause | select_clause | case_clause
                   | brace_group | subshell
```

После `then` `do` `else` `elif` `{` `in` `|` `&&` `||` перевод строки только пропускается: пустая команда из него не возникает. Между командами NL заканчивает команду (как `;`). Несколько пустых строк подряд допустимы. Пустая команда из `; ;` в язык не входит.

Хвостовой `;` у команды допустим. `&` — фон, только в конце `and_or`.

### Простая команда и присваивание

```
simple_command ::= word { argument } { redir }
argument       ::= word | ASSIGN
word           ::= имя | WORD | STRING | expansion
assignment     ::= ASSIGN
redir          ::= '>' word | '>>' word | '<' word | '2>' word | '2>&1'
```

Имя команды — то же `word`, что аргумент без присваивания: `echo`, `"echo"`, `$cmd`, `$(echo echo)`.

Редиректы стоят в конце простой команды, проверки `[ ... ]` и составной команды: `if`, `while`, `until`, `for`, `select`, `case`, группа и подшелл. После присваивания, функции и `local` их нет. Цель `>`, `>>`, `<` и `2>` — `word`: имя, обычное слово, строка или подстановка (`> "$file"`, `> $name`, `> $(echo /tmp/f)`). Конструкция `FOO=1` целью не бывает.

`ASSIGN` в начале команды как единственный элемент — присваивание: `FOO=1`.  
`ASSIGN` среди аргументов — обычный аргумент: `echo FOO=1`.  
Префикс `FOO=1 echo x` в язык не входит.

### `[ ... ]`

```
test_command ::= '[' { argument } ']' { redir }
```

Операторы теста (`-lt`, `=`, `-f`, …) не проверяются: это слова. `[[` в язык не входит. Хвостовой редирект необязателен, в том числе когда проверка стоит в условии.

```
[ -f "$file" ] > /tmp/out
if [ -f "$file" ] 2> /tmp/err; then echo ok; fi
```

### if / while / until

Условие — один `and_or`: простая команда, `[ ... ]`, конвейер или цепочка `&&` / `||`. Перед `then` и `do` нужны `;` или перевод строки. Две команды через `;` в условие не входят. `[[` в язык не входит.

```
if_clause    ::= IF and_or ( ';' | NL ) THEN [ NL ] body
                 { ELIF and_or ( ';' | NL ) THEN [ NL ] body }
                 [ ELSE [ NL ] body ]
                 FI

while_clause ::= WHILE and_or ( ';' | NL ) DO [ NL ] body DONE
until_clause ::= UNTIL and_or ( ';' | NL ) DO [ NL ] body DONE
```

`body` здесь — последовательность `complete_command` (вложенность составных команд можно).

```
if [ "$1" = a ]; then echo x; fi
if true; then echo x; fi
if grep -q x "$file"; then echo found; fi
if echo a | grep a; then echo ok; fi
while true; do echo x; done
```

### for

```
for_clause ::= FOR ID IN { argument } ( ';' | NL ) DO [ NL ] body DONE
             | FOR ID ( ';' | NL ) DO [ NL ] body DONE
```

Вторая форма — цикл без `in`. По списку слов распознаватель не ходит.

```
for name; do
  echo "$name"
done
```

### select

Та же пара форм, что у `for`. Переменная `REPLY` и меню — семантика оболочки, распознаватель их не проверяет.

```
select_clause ::= SELECT ID IN { argument } ( ';' | NL ) DO [ NL ] body DONE
                | SELECT ID ( ';' | NL ) DO [ NL ] body DONE
```

### Группа и подшелл

Группа использует то же тело, что функция.

```
brace_group ::= '{' [ NL ] body '}'
subshell    ::= '(' body ')'
```

Перед `}` в непустой группе нужны `;` или перевод строки: `{ echo x; }`, а `{ echo x }` в язык не входит. Пустые `{ }` и `( )` допустимы.

Подшелл — список команд в круглых скобках, в том числе вложенный. Пробел между скобками сканер выбрасывает, поэтому `((echo z))` — два подшелла. Выражение в этих скобках не вычисляется.

```
{ echo x; }
( echo y )
((echo z))
{ echo x; } > out
( echo y ) | cat
```

### case

Каждый пункт, включая последний, заканчивается `;;`.

```
case_clause ::= CASE argument IN [ NL ] { case_item } ESAC
case_item   ::= pattern { '|' pattern } ')' [ NL ] body ';;' [ NL ]
pattern     ::= WORD | STRING
```

### Функции и local

```
function_def ::= ID '(' ')' [ NL ] brace_group
               | FUNCTION ID [ '(' ')' ] [ NL ] brace_group
local_stmt   ::= LOCAL { ID | ASSIGN }
```

Тело функции — та же `brace_group`, что у группы. Перед `}` нужен `;` или NL (`name() { echo x; }`, не `name() { echo x }`).

Область `local` (только внутри функции) не проверяется.

## Вне языка

В том числе: `#!/usr/bin/env bash`; here-doc `<<`; `<( )`; `` `...` ``; `[[ ]]`; арифметический цикл `for (( ... ))`; `${var:-x}` `${var/pat/repl}`; массивы `a=(...)` `${a[@]}`; `source` / `.`; `coproc`; префикс `VAR=val cmd`; байты вне ASCII. Скобки команды — у функции, группы, подшелла, `$(...)`, `[...]` и `case`.

`$((count + 1))` на месте команды — команда, имя которой подстановка. Значение не вычисляется. В аргументе та же запись читается как `$( ( count + 1 ) )`: `echo $((count + 1))`.

Ключевые слова распознаются в любой позиции (`echo done`, `echo in`). Вне кавычек отвергается `\`. Символы `[ ] { }` не входят в слово (`ls [abc]*`, `echo {a,b}`). Не принимаются `if ! [ ... ]` и шебанг с `\r` (CRLF даёт `extra text in shebang`).

## Примеры

Принятие:

```
#!/bin/bash
echo "Hello, $name!"
count=0
if [ $# -lt 2 ]; then
  echo usage
fi
```

Отказ (нет шебанга) — `Error: line 1: missing shebang`:

```
echo hello
```

Отказ (в условии две команды) — `Error: line 2`:

```
#!/bin/bash
if true; false; then echo x; fi
```

Исполняемые примеры: `tests/accept/`, `tests/reject/` (`*.line` — ожидаемый `N`, необязательный `*.msg` — пояснение). Запуск: `tests/run.sh`.
