# bash-cw

Входной язык распознавателя. Это учебное подмножество синтаксиса bash, не шелл и не «весь bash». Принадлежность текста языку определяет грамматика ниже, а не поведение GNU bash.

## Контракт распознавателя

Вход: путь к файлу `.sh` (или stdin, если путь не дан).

| Исход | stdout | stderr | код |
|---|---|---|---|
| текст ∈ bash-cw | пусто | пусто | 0 |
| иначе | пусто | `Error: line N` или `Error: line N: text` | 1 |

`N` — номер строки (с 1), на которой обнаружена ошибка. Дальше разбор не идёт. Для токена перевода строки flex увеличивает счётчик при чтении этого символа, поэтому ошибка на таком токене относится к следующей строке. Пояснение `text` есть у шебанга (`missing shebang`, `extra text in shebang`), у here-документа (`here-document is not supported`), у байта без токена (`unexpected character`), у незакрытой строки (`unterminated single quote`, `unterminated double quote` — номер строки открывающей кавычки) и у псевдоправил: `[[ ... ]] is not supported`, `missing ';' or newline before then`, `missing ';' or newline before do`, `missing ';' or newline before '}'`, `unexpected then`, `unexpected do`, `case requires in`, `case item must end with ;;`.

Строка шебанга — строка 1. Пустой файл — `Error: line 1: missing shebang`.

## Программа

Файл начинается с шебанга. Комментарии и команды — только после него.

```
program     ::= shebang [ NL body ]
shebang     ::= '#!/bin/bash' [ spaces ]
body        ::= { NL | comment NL | complete_command }
```

- Шебанг — ровно `#!/bin/bash`, затем только пробелы/табы до конца строки. Не `#!/usr/bin/env bash`, не аргументы после пути.
- Файл из одного шебанга (с NL или без) принадлежит языку.
- Пустой файл не принадлежит.
- Текст — ASCII. Байт вне ASCII — `unexpected character` на этой строке.
- Конец строки — `\n`.

Комментарий: `#` до конца строки, если `#` стоит на границе токена (после пробела, `;`, NL, в начале строки тела). `#` внутри слова не начинает комментарий (`$#` — подстановка, `foo#bar` — одно слово). Внутри `'...'` / `"..."` комментариев нет.

## Токены

Пробел и таб разделяют токены и иначе незначимы.

**Ключевые слова** (только целиком, не часть слова):  
`if` `then` `elif` `else` `fi` `while` `until` `do` `done` `for` `select` `in` `case` `esac` `function` `local`

**Операторы:**  
`|` `||` `&` `&&` `;` `<` `>` `>>` `2>` `2>&1` `(` `)` `{` `}` `[` `]`

**Имя (`ID`):** `[A-Za-z_][A-Za-z0-9_]*`

**Присваивание (`ASSIGN`):** `ID=` или `ID=` сразу за ним значение без пробела, если это WORD (`count=0`, `name=`, `path=/tmp/a`). Пробел вокруг `=` запрещён: `name = 1` — три отдельных слова, не присваивание. Кавычка и `$` в WORD не входят, поэтому сканер их не склеивает с `ID=`. `name="World"`, `name=$1` и `n=$((1 + 2))` — лексема `ASSIGN` и следом слово. Это пустой префикс и команда, а не значение присваивания.

**Слово (`WORD`):** непробельная последовательность ASCII без операторов, кавычек и `#` на границе. В том числе `echo`, `apt-get`, `foo/bar`, `-lt`, `--help`, `+x`, `2`, `*.txt`.

**Строка:** `'...'` или `"..."`. Это один токен.

- Внутри кавычек подстановки **не** разбираются: `"Hello, $name!"` — строка, не `$name`.
- В одинарных кавычках `'` внутри быть не может. Обратная косая черта там обычный байт.
- В двойных `\"` и `\\` не закрывают строку. Обратная косая черта прячет и перевод строки, поэтому кавычки могут перейти на следующую строку файла и остаться одним токеном.
- Перевод строки внутри кавычек входит в ту же строку. Комментарий там не начинается.
- Если закрывающей кавычки нет до конца файла, ошибка на строке открывающей кавычки: `unterminated single quote` или `unterminated double quote`.
- Пустые `''` и `""` допустимы.

**Подстановка** (только вне кавычек):

- `$ID` `$`+цифры `$#` `$@` `$*` `$$` `$?`
- `${ID}` — голое имя, без `:-`, `/` и прочего
- `${!ID}` — то же с `!` сразу после `{`. Индекса у этой формы нет: `${!name[0]}` не входит
- `${ID[число]}`, `${ID[имя]}`, `${ID[@]}`, `${ID[*]}` — индекс. Среза `${ID[@]:1}` и длины `${#ID[@]}` нет
- `$( list )` — внутри тот же список команд, что в теле программы, без шебанга; вложенность можно
- `$(( ... ))` — одна лексема `ARITH` и тоже подстановка, то есть `word`. Внутри одна или больше букв, цифр, пробелов и знаков `+ - * / % < > = ! & | ^`. Таба, перевода строки, `$`, кавычек и вложенных скобок в этой лексеме нет. Формула не проверяется и не вычисляется: подходят и `$((count + 1))`, и `$((1+))`. `echo $((count + 1))` — команда с таким аргументом. Одинокое `$((count + 1))` — команда, имя которой эта подстановка. Пустое `$(())` под правило не попадает и читается как `$(` и подшелл. Если внутри есть байт вне этого набора, текст тоже читается как `$(`, а не как `ARITH`.

## Команды

```
complete_command ::= and_or [ ';' | '&' ] [ NL ]
                   | and_or NL

and_or           ::= pipeline
                   | pipeline '&&' [ NL ] and_or
                   | pipeline '||' [ NL ] and_or

pipeline         ::= command
                   | command '|' [ NL ] pipeline

command          ::= simple_command
                   | test_command
                   | compound_command { redir }
                   | function_def
                   | local_stmt

compound_command ::= if_clause | while_clause | until_clause
                   | for_clause | select_clause | case_clause
                   | brace_group | subshell
```

После `then` `do` `else` `elif` `{` `in` `|` `&&` `||` перевод строки только пропускается: пустая команда из него не возникает. Между командами NL заканчивает команду (как `;`). Несколько пустых строк подряд допустимы. Пустая команда из `; ;` в язык не входит.

Хвостовой `;` у команды допустим. `&` — фон, только в конце `and_or`.

### Простая команда и присваивание

```
simple_command ::= assign_list
                 | assign_list word { argument } { redir }
                 | word { argument } { redir }
assign_list    ::= ASSIGN
                 | assign_list ASSIGN
argument       ::= word | ASSIGN
word           ::= имя | WORD | STRING | expansion
redir          ::= '>' word | '>>' word | '<' word | '2>' word | '2>&1'
```

Имя команды — то же `word`, что аргумент без присваивания: `echo`, `"echo"`, `$cmd`, `$(echo echo)`, `$((count + 1))`.

Редиректы стоят в конце простой команды, у которой есть имя, у проверки `[ ... ]`, у объявления функции и у составной команды: `if`, `while`, `until`, `for`, `select`, `case`, группа и подшелл. У голого `assign_list` и у `local` их нет. Цель `>`, `>>`, `<` и `2>` — `word`: имя, обычное слово, строка или подстановка (`> "$file"`, `> $name`, `> $(echo /tmp/f)`). Конструкция `FOO=1` целью не бывает.

`assign_list` без следующего слова — присваивание: `FOO=1`, `a=1 b=2`.  
Следующее слово — имя команды: `FOO=1 echo x`, `a=1 b=2 echo y`.  
`ASSIGN` среди аргументов — обычный аргумент: `echo FOO=1`.

### `[ ... ]`

```
test_command ::= '[' { argument } ']' { redir }
```

Операторы теста (`-lt`, `=`, `-f`, …) не проверяются: это слова. `[[` даёт `Error: line N: [[ ... ]] is not supported`. Пробел между скобками сканер выбрасывает, поэтому `[ [` — тот же отказ. Хвостовой редирект необязателен, в том числе когда проверка стоит в условии.

```
[ -f "$file" ] > /tmp/out
if [ -f "$file" ] 2> /tmp/err; then echo ok; fi
```

### if / while / until

Условие — один `and_or`: простая команда, `[ ... ]`, конвейер или цепочка `&&` / `||`. Перед `then` и `do` нужны `;` или перевод строки. Склейка `if true then` и `while true do` даёт пояснение `missing ';' or newline before then` или `before do`. Две команды через `;` в условие не входят.

```
if_clause    ::= IF and_or ( ';' | NL ) THEN [ NL ] body
                 { ELIF and_or ( ';' | NL ) THEN [ NL ] body }
                 [ ELSE [ NL ] body ]
                 FI

while_clause ::= WHILE and_or ( ';' | NL ) DO [ NL ] body DONE
until_clause ::= UNTIL and_or ( ';' | NL ) DO [ NL ] body DONE
```

`body` здесь — последовательность `complete_command` (вложенность составных команд можно).

```
if [ "$1" = a ]; then echo x; fi
if true; then echo x; fi
if grep -q x "$file"; then echo found; fi
if echo a | grep a; then echo ok; fi
while true; do echo x; done
```

### for

```
for_clause ::= FOR ID IN { argument } ( ';' | NL ) DO [ NL ] body DONE
             | FOR ID ( ';' | NL ) DO [ NL ] body DONE
```

Вторая форма — цикл без `in`. По списку слов распознаватель не ходит.

```
for name; do
  echo "$name"
done
```

### select

Та же пара форм, что у `for`. Переменная `REPLY` и меню — семантика оболочки, распознаватель их не проверяет.

```
select_clause ::= SELECT ID IN { argument } ( ';' | NL ) DO [ NL ] body DONE
                | SELECT ID ( ';' | NL ) DO [ NL ] body DONE
```

### Группа и подшелл

Группа использует то же тело, что функция.

```
brace_group ::= '{' [ NL ] body '}'
subshell    ::= '(' body ')'
```

Перед `}` в непустой группе нужны `;` или перевод строки: `{ echo x; }`. Запись `{ echo x }` даёт `missing ';' or newline before '}'`. Пустые `{ }` и `( )` допустимы.

Подшелл — список команд в круглых скобках, в том числе вложенный. Пробел между скобками сканер выбрасывает, поэтому `((echo z))` — два подшелла. Выражение в этих скобках не вычисляется.

```
{ echo x; }
( echo y )
((echo z))
{ echo x; } > out
( echo y ) | cat
```

### case

Каждый пункт, включая последний, заканчивается `;;`. Без `;;` перед `esac` сообщение `case item must end with ;;`. Без `in` сообщение `case requires in`.

```
case_clause ::= CASE argument IN [ NL ] { case_item } ESAC
case_item   ::= pattern { '|' pattern } ')' [ NL ] body ';;' [ NL ]
pattern     ::= WORD | STRING
```

### Функции и local

```
function_def ::= ID '(' ')' [ NL ] brace_group
               | FUNCTION ID [ '(' ')' ] [ NL ] brace_group
local_stmt   ::= LOCAL { ID | ASSIGN }
```

Тело функции — та же `brace_group`, что у группы. Перед `}` нужен `;` или NL. `name() { echo x }` даёт то же пояснение, что группа: `missing ';' or newline before '}'`. После закрывающей скобки можно поставить редирект: `name() { echo x; } > out`. Хвост может быть пустым.

`then` и `do` на месте команды дают `unexpected then` и `unexpected do`. `fi`, `done`, `else`, `elif` и `esac` так не помечены: они закрывают тело, и пустое тело нельзя отличить от команды из одного этого слова.

Область `local` (только внутри функции) не проверяется.

## Вне языка

В том числе: `#!/usr/bin/env bash`; here-doc `<<`; `<( )`; `` `...` ``; `[[ ]]`; команда `(( ... ))` и арифметический цикл `for (( ... ))`; `${var:-x}` `${var/pat/repl}` `${a[@]:1}` `${#a[@]}`; присваивание массива `a=(...)`; `source` / `.`; `coproc`; байты вне ASCII. Скобки команды — у функции, группы, подшелла, `$(...)`, `[...]` и `case`. Запись `((echo z))` остаётся двумя подшеллами: арифметика распознаётся только как `$(( ... ))`.

Ключевые слова распознаются в любой позиции (`echo done`, `echo in`). Вне кавычек `\` и `` ` `` дают `unexpected character`. Символы `[ ] { }` не входят в слово (`ls [abc]*`, `echo {a,b}`). Не принимаются `if ! [ ... ]` и шебанг с `\r` (CRLF даёт `extra text in shebang`).

## Примеры

Принятие:

```
#!/bin/bash
echo "Hello, $name!"
count=0
echo $((count + 1))
if [ $# -lt 2 ]; then
  echo usage
fi
```

Отказ (нет шебанга) — `Error: line 1: missing shebang`:

```
echo hello
```

Отказ (в условии две команды) — `Error: line 2`:

```
#!/bin/bash
if true; false; then echo x; fi
```

Исполняемые примеры: `tests/accept/`, `tests/reject/` (`*.line` — ожидаемый `N`, необязательный `*.msg` — пояснение). Запуск: `tests/run.sh`.
