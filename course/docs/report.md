# 1. Цель и задачи

Цель — самостоятельно построить грамматику учебного подмножества синтаксиса bash и реализовать распознаватель на lex/yacc (flex + bison в режиме `-y`).

Задачи:
- зафиксировать входной язык bash-cw (это не GNU bash и не «весь bash»);
- описать лексемы регулярными выражениями;
- описать синтаксис контекстно-свободной грамматикой;
- сообщать номер строки первой ошибки;
- проверить распознаватель наборами принимаемых и отвергаемых текстов.

# 2. Входной язык bash-cw

bash-cw — учебное подмножество синтаксиса bash. Принадлежность текста языку определяет грамматика распознавателя, а не поведение GNU bash.

Программа начинается с шебанга `#!/bin/bash` (после пути только пробелы/табы). Файл из одного шебанга принадлежит языку; пустой файл — нет. Текст ASCII, конец строки — `\n`.

В языке есть:
- простые команды, конвейеры `|`, списки `&&` / `||`, фон `&`;
- присваивания `NAME=value` без пробелов вокруг `=`;
- редиректы `> >> < 2> 2>&1` в конце простой команды;
- проверка `[ ... ]`;
- `if` / `elif` / `else` / `fi`, `while` / `until` / `do` / `done`, `for ID in ...`, `case` / `esac`;
- функции (`name() { ...; }` и `function name { ...; }`), `local`;
- подстановки `$name`, `$1`, `$# $@ $* $$ $?`, `${name}`, `$( ... )`;
- строки `'...'` / `"..."` (внутри кавычек `$` не разбирается).

Вне языка, в том числе: `#!/usr/bin/env bash`; here-doc; `` `...` ``; `[[ ]]`; `(( ))` / `$(( ))`; `${var:-x}`; массивы; группы `{ ...; }` и подшелл `( ... )` как команды; префикс `VAR=val cmd`.

Условие `if`/`while`/`until` — только `[ ... ]`, не любая команда.

# 3. Контракт распознавателя

Вход: путь к `.sh` или stdin.

| Исход | stdout | stderr | код |
|---|---|---|---|
| текст ∈ bash-cw | пусто | пусто | 0 |
| иначе | пусто | `Error: line N` | 1 |

`N` — строка первой ошибки (с 1). Дальше разбор не идёт.

# 4. Лексический анализатор

Реализован в `lex_bash.l` (flex). Стартовое состояние `INITIAL` принимает только шебанг, затем `BODY`.

Имена:
- `ID` — `[A-Za-z_][A-Za-z0-9_]*`
- `WORD` — непробельная последовательность без операторов и кавычек
- `ASSIGN` — `ID=` или `ID=` сразу за значением-словом (`count=0`, `name=`)

Ключевые слова (целиком, не часть слова):
`if then elif else fi while until do done for in case esac function local`

Операторы (длинные раньше коротких):
`2>&1` `2>` `>>` `&&` `||` `;;` `|` `&` `;` `<` `>` `(` `)` `{` `}` `[` `]`

Подстановки: `$ID`, `$`+цифры, `$# $@ $* $$ $?`, `${ID}`, `$(`.

Строки читаются вручную (`input()`): одинарные — до `'`, двойные — до `"`, внутри `\"` и `\\` не закрывают строку. Незакрытая строка и перевод строки внутри кавычек — ошибка на строке открытия.

Комментарий: `#` до конца строки, если `#` на границе токена. `$#` и `foo#bar` комментарием не являются.

Пробел и таб токены не порождают. Перевод строки — токен `NL` (разделитель команд).

# 5. Синтаксический анализатор

Реализован в `pars_bash.y` (bison `-y`). Стартовый символ `program`.

```
program      ::= SHEBANG list
list         ::= nl_opt [ stmt_seq [ separator ] ]
stmt_seq     ::= and_or { separator and_or }
separator    ::= ( ';' | '&' | NL ) nl_opt
and_or       ::= pipeline { ( '&&' | '||' ) nl_opt pipeline }
pipeline     ::= command { '|' nl_opt command }
command      ::= simple_command | assignment | test_command
               | if_clause | while_clause | until_clause
               | for_clause | case_clause | function_def | local_stmt
```

Простая команда: имя, аргументы, редиректы только в конце.
`FOO=1` — присваивание; `echo FOO=1` — аргумент; `FOO=1 echo x` в язык не входит.

`if` / `while` / `until` требуют `[ ... ]` и разделитель `;` или NL перед `then`/`do`.
`case`: каждый пункт, включая последний, заканчивается `;;`.
Перед `}` нужен `;` или NL: `name() { echo x; }`, не `name() { echo x }`.

Подстановка `$( list )` разбирает тот же список команд, без шебанга; вложенность допускается.

# 6. Конфликты грамматики

`bison -v`: **1 shift/reduce**, reduce/reduce нет.

Конфликт в `local_item` на токене `ID` после `ASSIGN`:

```
local a= b
```

- shift: один элемент `ASSIGN word` (`a=` со значением `b`);
- reduce: два элемента (`a=` и имя `b`).

Bison берёт shift. Обе ветки принимают текст, распознаватель дерево не строит — на исход (принять/отвергнуть) не влияет. Остальные правила (в том числе `NL` как разделитель vs. пустые строки) LALR разруливает без конфликтов.

# 7. Обработка ошибок

`yyerror` печатает `Error: line N` в stderr (`N` = `yylineno`) и не пишет в stdout. Лексер на шебанге, незакрытой строке и недопустимом символе вызывает ту же функцию и завершается с кодом 1. Разбор после первой ошибки не продолжается.

# 8. Сборка и тестирование

Язык реализации — C. Bison в режиме совместимости с yacc (`-y`).

```
flex lex_bash.l
bison -d -y -v pars_bash.y
gcc -o bash_parser y.tab.c lex.yy.c
```

Тесты: `tests/run.sh`.
`tests/accept/*.sh` — код 0, оба потока пусты.
`tests/reject/*.sh` + `*.line` — код 1, stderr ровно `Error: line N`.

Покрыты шебанг, комментарии, присваивания, строки, подстановки, конвейеры, `&&`/`||`, `if`/`elif`/`else`, циклы, `for`, `case`, функции, `local`, редиректы, `$(...)`, фон, вложенный `if`. Отказы: нет шебанга, `env`-шебанг, `if true`, `[[`, here-doc, `((`, `${var:-x}`, массив, `{ ...; }` как команда, префикс `VAR=val cmd`, незакрытая строка.

# 9. Вывод

Построена своя грамматика bash-cw и распознаватель на flex/bison. Программа решает принадлежность текста языку: при принятии молчит, при отказе указывает строку. Грамматика LALR с одним безвредным конфликтом. Ограничение работы — учебное подмножество, а не полный GNU bash.
